Artificial intelligence is the simulation of human intelligence by machines.
Document understanding involves extracting meaningful information and insights from structured or unstructured text.
Retrieval-Augmented Generation, commonly known as RAG, combines information retrieval with text generation.
The retrieval component searches a document index using TF-IDF and cosine similarity to find relevant chunks.
The Transformer is a deep learning architecture that relies on self-attention mechanisms to process sequential data.
In a decoder-only Transformer, causal masking prevents tokens from attending to future positions during text generation.
Multi-head attention allows the model to jointly attend to information from different representation subspaces.
Residual connections and layer normalization help stabilize and accelerate the training of deep neural networks.
The language model head projects the contextualized embeddings onto vocabulary logits to predict the next token.
Offline document assistants operate locally without requiring cloud APIs or internet connectivity, ensuring data privacy.

Code: class TextDataset | Summary: Sliding-Window Autoregressive Next-Token Dataset for Language Modeling. Academic / Viva Reference: - What it does: Converts a continuous stream of token IDs into paired input-target sequences (x, y) where y is identical to x shifted by 1 position forward in time. - Why it is needed: 1. Self-Supervised Learning: Eliminates the need for manually labeled data by using the natural order of human text as the supervision signal. 2. Causal Alignment: Input x: [t_0, t_1, ..., t_{S-1}] Target y: [t_1, t_2, ..., t_S ] At every index i, the model attempts to predict y[i] given context x[0:i+1]. 3. Sliding Window: Using an overlapping stride extracts maximal training examples from compact domain corpora. - Output shapes: - x: (seq_len,) with dtype torch.long - y: (seq_len,) with dtype torch.long

Code: class Tokenizer | Summary: Character-level Tokenizer with Special Token support for the Transformer. Academic / Viva Reference: - What it does: Converts raw human text into discrete integer token sequences and back. - Tokenization Trade-offs (Classic Viva Question): 1. Word-level: Large vocabulary (50k-100k+), struggles with unseen words (OOV) and morphology. 2. Code: class DocumentRetriever | Summary: TF-IDF Document Retriever with Cosine Similarity for Offline RAG. Academic / Viva Reference: - What it does: Indexes unstructured document passages into sparse TF-IDF vectors and retrieves the most semantically relevant context chunks for an input query. - Why it is needed: 1. Non-Parametric Memory: Language models have fixed parametric weights; RAG dynamically supplies relevant up-to-date document knowledge without retraining. 2. Grounding & Anti-Hallucination: Conditioning generation on retrieved factual passages enforces factual accuracy. 3. Fully Offline & Fast: Uses pure vector-space mathematics (TF-IDF + Cosine Similarity) requiring zero external vector databases, cloud APIs, or GPUs. - Mathematical Formulation: - Term Frequency: TF(t, d) = count(t, d) / len(d) - Inverse Document Frequency: IDF(t, D) = ln((1 + |D|) / (1 + DF(t))) + 1 - TF-IDF Weight: w(t, d) = TF(t, d) * IDF(t) - Cosine Similarity: sim(q, d) = (q . d) / (||q|| * ||d||)

Code: class CausalSelfAttention | Summary: Causal Multi-Head Self-Attention Layer for the Decoder-Only Transformer. Academic / Viva Reference: - What it does: Computes scaled dot-product attention across multiple representation subspaces simultaneously, enforcing autoregressive causality. - Why it is needed: 1. Self-Attention: Allows tokens to dynamically weigh the importance of other tokens in the context. 2. Multi-Head: Enables the model to jointly attend to information from different representation subspaces at different positions (e.g., syntactic vs. semantic relationships). 3. Causal Masking: Prevents current tokens from attending to subsequent tokens (future information), preserving the autoregressive property required for generative language modeling. - Input shape: (batch_size, seq_len, d_model) - Output shape: (batch_size, seq_len, d_model) - Mathematical Formulation: Q = X * W_q, K = X * W_k, V = X * W_v Scores = (Q * K^T) / sqrt(d_k) Masked_Scores = Scores + M, where M_ij = 0 if j <= i else -inf Attention_Weights = softmax(Masked_Scores, dim=-1) Head_Out = Attention_Weights * V MultiHead_Out = Concat(head_1, ..., head_h) * W_o

Code: class TransformerBlock | Summary: Transformer Decoder Block with Pre-Layer Normalization and Residual Connections. Academic / Viva Reference: - What it does: Chains Causal Multi-Head Self-Attention and Position-Wise Feed-Forward sublayers with Layer Normalization and Residual Connections. - Why it is needed: 1. Layer Stacking: Multiple identical blocks allow the model to build hierarchical semantic and syntactic representations of sequential context. 2. Residual Connections (Skip Connections): x_next = x + Sublayer(x). Provides an unbroken gradient highway directly through the network, preventing vanishing gradients in deep models. 3. Pre-LN vs Post-LN: - Post-LN: x = LayerNorm(x + Sublayer(x)) [Attention Is All You Need, 2017] - Pre-LN: x = x + Sublayer(LayerNorm(x)) [Modern LLMs: GPT-2, GPT-3, LLaMA] Pre-LN significantly stabilizes training from step 0, avoiding sensitive learning rate warmups. - Input shape: (batch_size, seq_len, d_model) - Output shape: (batch_size, seq_len, d_model) - Mathematical Formulation: h_1 = x + CausalSelfAttention(LayerNorm_1(x)) h_2 = h_1 + FeedForward(LayerNorm_2(h_1))

Code: class TokenEmbedding | Summary: Token Embedding Layer for the Transformer. Academic / Viva Reference: - What it does: Maps discrete integer token IDs into continuous dense vectors. - Why it is needed: Neural networks operate on continuous vector spaces, not discrete symbols. - Input shape: (batch_size, seq_len) with dtype torch.long - Output shape: (batch_size, seq_len, d_model) with dtype torch.float32 - Mathematical operation: E(X) = X * W_E, where W_E in R^(vocab_size x d_model)
Code: class PositionalEmbedding | Summary: Learned Positional Embedding Layer for the Transformer. Academic / Viva Reference: - What it does: Encodes sequential order of tokens into continuous dense vectors. - Why it is needed: Self-attention is permutation-invariant; without positional embeddings, the network treats sequences as unordered bags of tokens. - Input: Tensor of shape (batch_size, seq_len) or integer sequence length. - Output shape: (1, seq_len, d_model), broadcastable across batches. - Mathematical operation: P = [0, 1, ..., seq_len - 1], E_pos = Embedding(P, W_pos)
Code: class TransformerEmbedding | Summary: Combined Token and Positional Embedding Layer for the Transformer. Academic / Viva Reference: - What it does: Sums token embeddings and positional embeddings elementwise, then applies dropout. - Why it is needed: Merges identity information (which token) with structural information (where it appears) into a single representation vector per token position before self-attention. - Input shape: (batch_size, seq_len) with dtype torch.long - Output shape: (batch_size, seq_len, d_model) with dtype torch.float32 - Mathematical operation: E_final = Dropout(TokenEmbedding(X) + PositionalEmbedding(P))

Code: class FeedForward | Summary: Position-Wise Feed-Forward Network (FFN) for the Transformer Block. Academic / Viva Reference: - What it does: Applies two linear transformations with a non-linear activation in between, applied identically and independently to each token position. - Why it is needed: 1. Attention mechanisms perform dynamic linear aggregation across positions; the FFN supplies the deep non-linear expressive capacity. 2. Attention mixes representations across tokens, whereas the FFN processes intra-token feature interactions and functions as an associative memory store. 3. Expands the model dimensionality into a higher-dimensional space (typically 4 * d_model), allowing rich feature transformations before projecting back down. - Input shape: (batch_size, seq_len, d_model) - Output shape: (batch_size, seq_len, d_model) - Mathematical formulation: FFN(x) = Dropout(fc2(Activation(fc1(x)))) where: fc1: R^(d_model) -> R^(d_ff) fc2: R^(d_ff) -> R^(d_model) d_ff typically equals 4 * d_model

Code: class TransformerLM | Summary: Full Decoder-Only Autoregressive Transformer Language Model. Academic / Viva Reference: - What it does: Stacks N Transformer Decoder Blocks on top of token and positional embeddings, followed by final layer normalization and an affine language model head that projects hidden states to vocabulary logits. - Why it is needed: 1. Generative Modeling: Models the joint probability of a sequence of tokens by decomposing it autoregressively: P(w_1, ..., w_T) = prod_{t=1}^T P(w_t | w_1, ..., w_{t-1}). 2. Weight Tying: Ties the weights of the input token embedding and the output LM head (Press & Wolf, 2017). This cuts parameters nearly in half and improves generalization. 3. Deep Hierarchical Feature Extraction: Multiple stacked self-attention blocks allow lower layers to capture local syntax while higher layers capture global semantics. - Input shape: - idx: (batch_size, seq_len) with integer token IDs in [0, vocab_size - 1] - targets (optional): (batch_size, seq_len) with target token IDs for loss computation - Output shape: - logits: (batch_size, seq_len, vocab_size) - loss: scalar cross-entropy loss if targets are provided, else None
